# 🐕 汪汪时间管理局

> 一只卡通小狗 × 未来时间管理局的每日个人工作台
> Daily Doggy Dispatch · 一份每天更新的狗狗日程报

一个零依赖、开箱即用的手机端个人工作台。把「每日计划、习惯打卡、阅读、运动、记账、灵感」整合在一份会呼吸的日程报里，蓝色科技感底纹 + 手绘小狗 + 时间旅行元素，活泼有趣，同时保持信息清晰、适合长期使用。

可安装到手机桌面（PWA）、断网也能用、深色模式夜间不刺眼。

## ✨ 主题风格

- **视觉**：蓝色科技感底纹（浅蓝渐变 + 细密科技网格 + 顶部光晕），搭配 5 色轮转的活力模块色（翠绿 / 亮蓝 / 琥珀 / 珊瑚红 / 紫罗兰）

- **外观**：浅色 / 深色 / 跟随系统 三态；科技蓝 · 珊瑚橙 · 翠绿 三套主题色；小 / 标准 / 大 三档字号

## 🚀 快速开始

直接用浏览器打开 `index.html` 即可，无需安装、无需后端、无需构建。

```
workbench-mobile/
├── index.html              # 页面骨架：只放 DOM 结构与资源引用
├── manifest.webmanifest    # PWA 清单
├── sw.js                   # Service Worker（离线缓存）
├── src/
│   ├── css/                # 样式按层拆分，顺序即优先级
│   │   ├── 01-tokens.css       # 设计令牌：颜色/圆角/阴影/安全区/字号 + 深色与皮肤
│   │   ├── 02-base.css         # reset、页面底纹、布局容器、顶部栏
│   │   ├── 03-components.css   # 通用组件：卡片/区块/记录列表/导航/抽屉/弹窗
│   │   ├── 04-features.css     # 业务样式：洞察图表/月历/记账/搜索/任务增强
│   │   └── 05-system.css       # 系统层：安全面板/性能/手势/可访问性
│   └── js/                 # 逻辑按职责拆分，经典脚本共享全局作用域
│       ├── config.js           # ★ 唯一需要定制的地方：CONFIG + ICONS
│       ├── boot.js             # 启动装配（必须最后加载）
│       ├── core/               # date 日期周期 · utils 工具 · store 持久化 · router 视图路由
│       ├── ui/                 # charts 图表 · overlays 浮层 · records 记录层
│       │                       # drawer 抽屉 · gestures 手势 · panels 设置面板
│       ├── features/           # home 首页 · insight 洞察 · stats 统计
│       │                       # finance 记账 · notes 笔记 · todo 任务 · trash 回收站
│       ├── data/               # safety 快照与容量 · transfer 导入导出
│       └── system/             # a11y 可访问性 · theme 主题 · pwa 安装
└── workbench-assets/
    ├── greet-banner.jpg         # 首页 hero 插画（卡通小狗 × 时间机器）
    ├── avatar.jpg               # 抽屉默认头像
    ├── icon-192.png              # 应用图标
    ├── icon-512.png
    ├── icon-maskable-512.png     # Android 自适应图标
    └── apple-touch-icon.png      # iOS 主屏图标
```

### 🧩 为什么是多文件却仍能双击打开

脚本用的是**经典 `<script src>`**（不是 ES module），多个脚本共享同一个全局作用域，因此 `file://` 协议下也能正常加载——**双击 `index.html` 就能用，不需要起本地服务器、不需要打包**。

加载顺序即依赖顺序，写在 `index.html` 底部：

```
core(日期/工具) → config → core(store) → ui → features → data → system → boot
```

新增功能时：在 `src/js/` 对应目录下加文件，然后在 `index.html` 的脚本列表里按依赖顺序插一行即可。

> 建议在手机浏览器中打开以获得最佳体验；桌面浏览器也可正常使用（最大宽度 480px 居中布局）。
> 想用「添加到主屏幕 / 离线可用」，需要把整个目录部署到 `https` 或 `localhost`（例如 Gitee + Cloudflare Pages）。
>
> ⚠️ 改动 `src/` 下的文件结构后，记得同步 `sw.js` 里的预缓存清单并升级 `CACHE` 版本号，否则老用户会拿到混合版本的缓存。

### 📱 移动端显示与缩放

- **禁止双击放大**：三处配合。`index.html` 的 viewport 写 `maximum-scale=1.0, user-scalable=no`（管 Android 捏合），`src/css/02-base.css` 对 `html, body` 设 `touch-action: manipulation`（管双击放大，顺带去掉 300ms 点击延迟，单指滚动与卡片滑动不受影响），`src/js/system/a11y.js` 的 `bindZoomLock()` 做最后兜底（覆盖 iOS Safari 早期版本，仅拦截 300ms 内的第二次 `touchend`）。
- **字号无障碍兜底**：因为锁了系统缩放，请用「抽屉 → 主题与外观 → 字号」的三档字缩放（`--fs`）替代。
- ⚠️ **CSS 自定义属性里的 `url()` 按「声明它的样式表」的路径解析，不是相对 HTML**。`--greet-image` 声明在 `src/css/01-tokens.css`，所以必须写 `../../workbench-assets/greet-banner.jpg`（两级回退到项目根）。写成 `workbench-assets/…` 会被解析成 `src/css/workbench-assets/…` → 404，首页 hero 图静默空白、控制台只报一条 404。新增任何背景图 token 都按此规则。

## 🛠 技术实现

- **零依赖，无构建**：HTML + CSS + 原生 JavaScript，按模块拆成 24 个脚本 + 5 个样式表，无任何运行时依赖
- **模块边界**：`config`（定制）/ `core`（基础设施）/ `ui`（通用界面）/ `features`（业务模块）/ `data`（数据安全）/ `system`（主题·无障碍·PWA）/ `boot`（装配）
- **数据存储**：浏览器 `localStorage`，数据仅保存在当前设备的当前浏览器中
- **样式架构**：颜色 / 圆角 / 阴影 / 背景图 / 安全区 / 字号缩放全部通过 CSS 变量（`:root` token）管理；深色模式是 `html[data-theme="dark"]` 令牌覆盖，组件零改动
- **PWA**：`manifest.webmanifest` + Service Worker（静态资源 cache-first、页面导航 network-first），可装机、可离线
- **性能**：记录列表 > 50 条自动分页 + 滚动加载；记录级交互走事件委托；勾选/打卡只做局部重绘；首屏骨架屏
- **无障碍**：三档字号（`--fs` 缩放系数）、`aria-*` 语义、键盘可达、`prefers-reduced-motion`
- **图标**：内联 SVG 线性图标（Lucide 规范），不依赖图标字体或网络；图标对读屏默认隐藏
- **响应式**：底部 Tab 栏、抽屉导航、底部弹窗，适配手机安全区与软键盘

## ⚠️ 数据说明（重要）

- 你填写的所有内容**只保存在这台设备的这个浏览器里**。
- 换台电脑、换个浏览器、或者清空浏览记录，之前的数据就没了。
- 手机端和电脑端数据默认各记各的；开启「云端同步」后可跨设备同步（见下方章节）。
- 多人共享（同一账号多人同时编辑）暂不支持，同步为整包覆盖而非逐项合并。

## ☁️ 云端同步（多设备同步）

抽屉 →「数据工具」→「云端同步」可开启账号与同步（需部署后端，见下方「部署后端」）：

- **注册 / 登录**：账号体系基于 Cloudflare D1 + PBKDF2 密码哈希 + HttpOnly Cookie 会话，密码不以明文存储或下发。
- **双向同步（手动选方向）**：
  - **同步到云端** —— 把本机整包数据覆盖到云端，其他设备随时可拉取；
  - **从云端同步** —— 用云端整包数据覆盖本机（会覆盖本机全部数据，操作前二次确认）。
- **自动降级**：未部署后端时面板显示「不可用」，应用照常纯本地运行，数据不受影响。
- **注意**：同步是「整包覆盖」而非逐项合并——同一账号在两台设备分别改动后同步，后同步的一方会整体覆盖先前的云端副本。重要改动请先「导出数据」留底。

### 🖥 部署后端（Cloudflare Pages Functions + D1）

1. 在 Cloudflare 创建 D1 数据库：库名 `dev`，记下 `database_id`。
2. 把 `database_id` 填入根目录 `wrangler.toml` 的 `[[d1_databases]]`（仓库已预填默认 id）。
3. 建表：`wrangler d1 execute dev --remote --file=./schema.sql`（表带 `wbm_` 前缀：`wbm_users` / `wbm_sessions`）。
4. 部署：`wrangler pages deploy .`（或把仓库连到 Cloudflare Pages，Functions 目录 `functions/` 会被自动识别）。
5. 在 Pages 项目设置里绑定 D1（binding 名 `DB`，对应 `dev` 库）。

接口路径：`/api/register`、`/api/login`、`/api/logout`、`/api/me`（GET 取云端数据、PUT 上报本地整包）。

### 🛟 自动快照与回滚

每次进入新的一天，应用会自动为「今天打开前」的状态存一份快照：

- 最多保留 **7 份**，总体积超过预算时自动丢弃最旧的；
- 数据体积过大时，快照会自动剥离图片只保留文字（会在列表里标注「不含图片」）；
- 抽屉 →「存储与安全」可查看空间占用分解、手动立即快照、一键回滚（**回滚前还会再存一份当前状态，所以回滚本身也可回滚**）。

### 📊 容量监控

「存储与安全」里有一条用量进度条（按 `localStorage` 字符量估算，常见上限约 5MB 量级）：

- 用量 ≥ 75% 提示整理，≥ 90% 报警；
- 空间告急时自动快照会主动让位，不再占用配额；
- 图片附件在编辑器里压缩到长边 ≤ 800px 才写入，超出阈值即时提示。

### 📤 数据备份与迁移

打开侧边抽屉，底部「数据工具」区提供：

- **导出数据**：可按模块勾选导出（可附带「外观与设置」），下载 `workbench-backup-YYYYMMDD.json`。
- **导入数据**：选择备份文件后二次确认；**只覆盖备份里声明的模块**，未包含的模块保持原样；导入前自动存一份快照。

> 备份文件结构：`app / version / storageKey / exportedAt / owner / modules / data`。
> `version` 目前为 **2**；导入 v1 老备份时会自动迁移（打卡布尔值 → 数值计数、补齐分类 / 预算 / 模板 / 回收站等字段）。也兼容直接导出的纯 `data` 对象。

## 🎨 自定义指南

所有可定制内容集中在 **`src/js/config.js`** 的 `CONFIG` 对象中（原来在 `index.html` 的 `<script>` 顶部）：

| 配置项 | 说明 |
| --- | --- |
| `owner` / `slogan` / `brand` | 抽屉品牌名、副标题、品牌字符 |
| `quotes` | 一周七天的每日一句 |
| `modules` | 模块列表，每个模块含 `key` / `name` / `icon` / `type` / `desc` / `seed` |
| `quickAdd` | 首页快速记录按钮 |
| `overview` | 首页概览环形的计算规则 |

修改 `:root` 中的 CSS 变量即可一键换肤，无需改动组件样式；`html[data-theme="dark"]` 下再补一份深色取值即可支持深色模式。
